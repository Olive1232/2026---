## 2. 为什么"丙"是对的

增量游戏的核心不是"挂机"，而是**复利**：

```
产出 → 投入升级 → 升级放大产出 → 回到第一步（每圈更大）
```

我们**只补这一条闭环**，战斗手感完全保留：

```
杀生物 → 扛尸体 → 丢进洞 → 洞喷钱 → 捡钱 → 去商店 → 换神剑
   ↑                                            │
   │                                            ↓
   └──── 用钱让「洞」成长，下次涌现更多 ←────────┘
              ★ 新增的复利环节 ★
```

**为什么复利挂在"洞"上，而不是别处**：

1. 策划需求 L135 **原文就有**"升级物品会改变洞的形态" —— 这是策划自己写的增量机制，只是没实现
2. "喂养一个永远更饿的洞"和世界观天然咬合，不是硬套
3. 洞已经是经济循环的中枢，改动面最小

**已有的机制在增量语境下天然咬合**（不是硬凑）：

| 已有/已规划机制 | 在增量结构里的角色 |
|---|---|
| 油 → 剑可被点燃 | 用升级解锁新能力 |
| 火焰蔓延 → 烧掉藤蔓 | 用新能力解锁新区域（标准增量结构） |
| 怪物刷新点（x 个 / 每 x 秒） | 稳定的资源流，增量游戏的地基 |
| 洞的形态变化 | 成长的**视觉反馈**（增量游戏的核心爽点之一） |

## 3. 关于"大数"：**本设计不需要**

D1 当初拒绝大数运算，那条**继续有效**。原因：

- 没有挂机收益 ⇒ 数值**只随玩家操作增长**，不随时间累积
- 单局时长有限 ⇒ 可达数值远小于 `int64` 上限（约 9.2×10¹⁸）
- 因此 `Wallet` 保持 `int` 即可

**唯一需要留意**：`int64` 溢出前**必须**先做封顶保护（见 M18），
但那是"防御性一行 clamp"，不是"引入大数库"。**不要为此引入 `BigNumber` 类。**

## 4. 复利脊柱的具体设计

### 4.1 洞的成长（M16 的核心）

```
洞的「饥渴度」= 累计献祭价值（永久保留，不因任何事清零）
       ↓ 每达到一个阈值
「涌现」倍率上升、洞的形态变化
       ↓ 每次献祭喷出更多钱
能买更贵的祭品 / 更好的剑
       ↓ 献祭更值钱的东西
洞更饥渴（回到第一步）
```

### 4.2 数值曲线（草案，**待策划给正式数值**）

两张曲线**必须分开**，这是增量游戏的标准做法：

| 曲线 | 草案 | 说明 |
|---|---|---|
| **成本曲线**（升到下一级要喂多少） | 几何增长，公比 `r_cost` | 决定节奏 |
| **收益曲线**（每级的涌现倍率） | 几何增长，公比 `r_gain` | 决定爽感 |

**两种开局方案**：

| 方案 | 公比 | 回本周期 | 适用 |
|---|---|---|---|
| **甲（推荐先做）** | `r_cost = r_gain` | **恒定**（每级涨同样的比例） | 容易调、不会失控，适合先验证手感 |
| **乙** | `r_cost > r_gain` | **逐级变长** | 成熟增量游戏的做法，能撑更长游戏时长 |

> **建议**：MVP 先用甲（比如 `r_cost = r_gain = 1.6`），
> 等玩法定型、需要拉长游戏时长时再切乙。**切乙时只改一张表，不动代码**——
> 所以两张曲线都要走 `.tres` 资源（见 §5 数据驱动）。

## 6. ⚠️ 两个必须先解决的缺口

### 6.1 D6「死亡后保留」目前**落不到代码上** —— 项目里没有死亡系统

事实核查：

- 策划需求 L109 原文：怪物"**不会对玩家造成伤害**"
- 全项目 `grep` 结果：没有任何 `death` / `respawn` / `game_over` 逻辑
- `Wallet.reset()` 的**唯一调用点**是 `TestArena.gd:61` 的**调试键 `KEY_4`**，不是游戏逻辑

**所以 D6 现在是一条"面向未来的决定"**：它把设计方向锁死了（以后加死亡时，默认保留进度），
但**当下没有代码可改**。

**必须先定的问题**：既然"不挂机 + 死了全保留"，那么**死亡的代价是什么？**

三条可选路（**需策划选一条**）：

| 选项 | 死亡的代价 | 说明 |
|---|---|---|
| **甲** | **代价 = 时间**，无资源惩罚 | 玩家必须自己走回战场、重新刷怪。与 D6 完全一致，最简单 |
| **乙** | 掉一部分**当局临时**资源，永久进度不动 | 需要新增"临时/永久"两层钱包，复杂度上升 |
| **丙** | 以 **prestige（重置换永久加成）** 替代死亡惩罚 | 增量游戏的标准形态。若走这条，M19 要提前 |

> **建议先按甲做**：零额外实现，且和"无挂机收益"一致 ——
> 没有挂机产出时，玩家唯一的投入就是**主动时间**，死亡浪费的正是时间，这已经是代价。

### 6.2 经济数值目前是**亏的**（与路线无关，但必须改）

看代码时发现的两处具体问题：

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **献祭几乎不赚** | `Hole.gd`：`value_multiplier = 1.5`、随机修正 `0.9~1.15` ⇒ 最坏 `1.5 × 0.9 = 1.35`；而一只蟑螂**只有 1 元** | 升一件 5 元的油要献祭 **5 只蟑螂**，没有增长感 |
| 2 | **喷币数量与总额不匹配** | 同上：`coin_count` 是 4~34 枚，而总额可能只有个位数 | 为 1 元的尸体喷 8 枚币，单枚太小、"涌现"的视觉冲击被稀释 |

**这两条在增量路线下必须重做**（曲线要指数化），在 roguelite 路线下也该调。
